# Transcript Studio M6.15

## Implemented changes

- Added a single-active-export task model with a task GUID, immutable project/media/transcript/output paths, status and cancellation token.
- Added `ExportTaskManager` and `ExportProcessManager`; cancellation terminates the launched Node.js process tree and waits for process exit and redirected output drainage.
- Export output is derived from the `.project.json` file and saved beside it as `<stem>.exported.mp4`; no Save As dialog is used.
- Each task receives `cache/render/job-<guid>/`; the rendered temporary MP4 is named `<stem>.exported-<guid>.mp4.tmp`.
- Project and page-plan snapshots are written under `cache/temp/` with `.tmp` suffixes.
- Remotion media copy and bundle are directed into the task cache. The renderer writes an intermediate `.mp4` (to preserve container inference) and renames it to the required `.mp4.tmp` name after rendering succeeds.
- A lightweight in-process MP4 box check (ftyp/moov/mdat) runs before committing the new video; no external FFprobe executable is required. Existing output is replaced only after validation. If the final replacement or first-time move fails, the old output remains where applicable and the new temporary file is retained for recovery.
- Added a cancel-export action to the active export notice. It cancels the task without exiting the application.
- Added a WPF close-confirmation dialog with the exact actions `继续导出` and `取消导出并退出`. Exit waits for task cancellation/process cleanup before closing WPF resources.
- Added conservative cleanup for task directories and temp snapshots older than seven days.
- Removed the tray menu minimum width and reduced item horizontal padding.

## Project cache layout

```text
<project-folder>/
  <stem>.project.json
  <stem>.exported.mp4
  cache/
    render/
      job-<guid>/
        media/
        bundle/
        render-output.mp4
        <stem>.exported-<guid>.mp4.tmp
    temp/
      project-snapshot-<guid>.json.tmp
      page-plan-<guid>.json.tmp
```

## Important implementation note

Remotion renders to an intermediate file ending in `.mp4` because FFmpeg/Remotion may infer the container from the final extension. After the render process closes successfully, the intermediate file is renamed to the required `.mp4.tmp` cache filename. The final project output is not replaced until validation succeeds.
