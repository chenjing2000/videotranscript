# Transcript Studio M6.13 — full code review

Date: 2026-11-05  
Review basis: `docs/skills/transcript-studio-code-review/SKILL.md`  
Scope: WPF/WebView2 host, React state and commands, core transcript/layout logic, Remotion/CLI export, local media streaming, subtitle Skill, tests and current documentation.

## Summary

The review found several correctness and lifecycle issues around active-edit export snapshots, failed source switching, export error classification, page-plan trust, hidden-word paragraph export and stream ownership. These were corrected with targeted changes. No architectural framework, dependency-injection layer or new event bus was introduced.

## Findings and corrections

### Correctness / data integrity

1. **MP4 export could omit an inline word edit that had not yet been committed.** The export command previously snapshotted `words` and reused the existing page plan without committing the active editor. It now validates and commits the active token, creates the export word snapshot from the committed value, and repaginates that exact snapshot before posting the export request. MP4 export is also blocked when an existing project failed validation, rather than silently exporting the blank fallback project.
2. **A malformed newly selected transcript could leave the previous pair visible while WPF had already switched its active source/media token.** The React failure path now clears the stale visible pair and editing state. `OpenPair` reads an existing project before switching the media token and active source; path collisions are rejected before the switch.
3. **Any MP4 rendering error was presented as a dependency-installation failure.** Only exceptions thrown while preparing Node/npm/Headless Shell now produce `dependency-failed`. Remotion render/output errors remain ordinary task errors in the floating notice stack.
4. **External page plans were structurally checked but not bound to the current visible word sequence.** `isPagePlan` now checks contiguous word indices, word IDs, page anchors, row bounds, non-overlap, viewport bounds, switch ordering and warning types. `ReaderCanvas` validates against its current visible words and recomputes the plan if the snapshot does not match.
5. **Plain-text export dropped a paragraph boundary when its marker was attached to a hidden word.** The right pane still displays that boundary after the hidden token; the text exporter now omits the token but preserves the boundary, without creating empty paragraphs.
6. **The local media response could retain a file handle if response creation/handoff failed.** `LocalMediaServer` now tracks ownership of the file/response stream and disposes whichever resource has not been transferred to WebView2.
7. **The optional M1 evidence capture assumed a `<video>` element and failed in audio-only mode.** It now selects either `video` or `audio` while preserving the same capture workflow.
8. **Invalid global-settings backups could collide within the same second and overwrite an earlier backup.** Backup names now include a short GUID and use non-overwriting `File.Move`.
9. **Direct CLI export had less project validation than the desktop/UI path.** A shared script-side admission function now validates project v2, source names, required subtitle SHA-256, media kind, canvas, export settings, style, and override IDs/types before a supplied project is used. A supplied but invalid JSON project value (including `null`) is rejected rather than treated as “no project”.

### Maintainability / documentation

- The outside-double-click listener is now refreshed only when the word array changes, instead of after every render.
- Removed a duplicate media-error state update.
- Updated current architecture/data-model/product/README and the subtitle schema reference to describe the M6.12 work-folder layout and M6.13 floating status behavior.
- Marked the M6.5 project-path note as historical and corrected the M6.11 plain-text export note so it no longer documents a SaveFileDialog or obsolete button order.
- Added source-level regression tests for the review corrections, including the token/basename boundary that prevents the local media endpoint from exposing arbitrary sibling or parent paths.

## Not verified / remaining issues

1. `npm ci` timed out in this environment. The partial dependency directory does not contain `@types/node`, React, Vite or Remotion. Consequently `npm run typecheck` / `npm run build` are **not verified**; the build currently stops at TS2688 (`Cannot find type definition file for 'node'`).
2. No .NET SDK is installed in this environment. WPF compilation, WebView2 integration, native media streaming and Windows dialogs are **not verified**.
3. No actual Remotion MP4 export was run. Audio/video duration, source-audio presence, page-boundary sync and output quality still require Windows acceptance testing.
4. **The Remotion render process still has no user-facing cancellation or render-time timeout.** The existing Cancel action targets only npm/browser dependency preparation. Adding render cancellation changes the task UX and process lifecycle, so it is left as a follow-up rather than silently changing the current contract.
