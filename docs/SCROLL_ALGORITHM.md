# Scroll model and conflict analysis

Let reading viewport height be `H=1600-videoHeight`, laid-out document height `D`, and maximum legal shift `M=max(0,D-H)`. The top of first row is aligned to reading panel top at t=0; no automatic centering. For all times `0<=Y(t)<=M`; if D<=H -> Y(t)=0 (allow empty space below last row). End of a long article should have last row bottom aligned with reading panel bottom `Y=M` and stop scrolling. Row heights and paragraph gaps come from final actual line positions, not hardcoded font multiplier.

For each line i: first visible word begins at a_i, last visible word ends at b_i. For transition i->i+1 after the current line's last word finishes, prefer duration `a_(i+1)-b_i` where >= 150ms; otherwise use 150ms, allowing overlap into next spoken line. Ease with `S(u)=(1-cos(pi*u))/2`. Queue/merge dense events to prevent position jumps; derive absolute Y(t) from precomputed events, not CSS independent animations or onPlayback callbacks. Shift as needed to keep currently spoken row near center when possible, constrained by max M. Tail planning targets Y=M before/during last row. Once M reached never overscroll.

**Unavoidable conflict**: if a line finishes 10ms before next starts, no algorithm can both restrict scrolling exclusively to silence and use >=150ms. Similarly many dense transitions may postpone last-row bottom arrival. Design explicitly prioritizes smooth motion + no blank overscroll, with bounded overlap; add test stress cases. Current reference engine queues intervals sequentially and meets no-teleport and no-overscroll properties, but may deliver late positioning for dense speeches. Improve and prove with tests before final V1 claim.
